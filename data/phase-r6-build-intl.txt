SECTION D: DESIGN RULES — MAKING APPS NOT LOOK AI-GENERATED
===================================================================

-- THE "AI SLOP" ANTI-PATTERN GUIDE --

CRITICAL RULES:
1. DO NOT use default Inter font — it screams "default template"
   INSTEAD: Use one of these alternatives:
   - Satoshi (https://github.com/itfoundry/satoshi) — modern grotesk, free
   - DM Sans (https://fonts.google.com/specimen/DM+Sans) — friendly, Google Fonts
   - General Sans (https://github.com/itfoundry/general-sans) — versatile, free
   - Cabinet Grotesk (https://github.com/itfoundry/cabinet-grotesk) — bold personality
   - Geist (https://github.com/vercel/geist-font) — Vercel's font, excellent

2. DO NOT use default Tailwind color palette exactly as-is
   INSTEAD: Create a custom palette with at least:
   - Brand primary (one hero color)
   - Brand secondary
   - Neutral gray scale (cool or warm, not pure #6b7280)
   - Semantic colors (success green, warning amber, error red)
   Tool: https://uicolors.app — generate tailwind color palette from any hex

3. DO NOT use shadcn/ui components without customization
   INSTEAD: Override these CSS variables at minimum:
   --radius: 0.75rem (or custom — 0.5rem = sharp, 1rem = round)
   --background + --foreground (use actual brand colors)
   Component-specific: card, badge, button borders — add subtle custom styles

4. DO NOT use AI-generated illustrations
   INSTEAD:
   - Humaaans (https://www.humaaans.com) — free human illustrations
   - unDraw (https://undraw.co) — free illustrations, customizable color
   - Blush (https://blush.design) — customizable illustrations
   - Or: use geometric patterns and icons, no illustrations at all

5. DO NOT use default spacing scale everywhere
   INSTEAD: Apply "breathing room" — generous padding on cards (p-6 or p-8), sections (py-16 or py-24)
   Shadcn default compact feels cramped and template-y

6. DO NOT use unstyled alert/dialog/toast components
   INSTEAD: Animate every UI feedback element:
   - Toasts: slide in from right with spring animation
   - Dialogs: scale + fade (scale(0.95) → scale(1))
   - Dropdowns: fade + slide down
   Use Framer Motion or CSS transitions: duration 200-300ms

7. DO NOT have flat, uneventful pages
   INSTEAD: Add subtle motion:
   - Stagger children on list pages (staggerChildren: 0.05)
   - Subtle hover effects on cards (translateY(-2px) + shadow increase)
   - Page transitions (optional but premium feel)
   Library: https://github.com/framer/motion (Framer Motion)

-- TYPOGRAPHY SYSTEM FOR PROFESSIONAL APPS --
   Heading font: Display/geometric (General Sans, Satoshi, Cabinet Grotesk) — bold, personality
   Body font: Readable/neutral (DM Sans, Inter Display, Geist Sans) — clean, readable
   Monospace: JetBrains Mono (https://github.com/JetBrains/JetBrainsMono) or Geist Mono
   Scale: Use a defined type scale (12-14-16-18-20-24-30-36-48-60-72)
   Line height: Headers 1.1-1.3, body 1.5-1.7

-- COLOR SYSTEM THAT FEELS HUMAN-DESIGNED --
   Background: Never pure white (#ffffff) — use #fafafa or #f8f9fa or your brand's off-white
   Dark mode: Never pure black (#000000) — use #0a0a0a or #09090b
   Cards: Always slightly lighter/darker than background (contrast within 10-15%)
   Borders: Subtle (opacity 0.08-0.12 in dark, 0.06-0.10 in light)
   Text: Never pure black text — use gray-900 (#171717) or near-black

-- ICONS --
   Best: Lucide Icons (https://github.com/lucide-icons/lucide) — MIT, shadcn default, 1000+ icons
   Alternative: Phosphor Icons (https://github.com/phosphor-icons/phosphor-icons) — 6 styles per icon
   Alternative: Tabler Icons (https://github.com/tabler/tabler-icons) — 4000+ icons, MIT
   AVOID: Font Awesome (heavy, overused), Material Icons (looks Android-native)

PROMPT CHAIN FOR BUILDING A COMPLETE SAAS APP IN 1-2 DAYS:

=== PHASE 1: SCAFFOLD (30 min) ===
Prompt 1: "Create a Next.js 14 app with App Router, TypeScript, Tailwind CSS, and shadcn/ui. Initialize with these components: button, card, input, label, dialog, dropdown-menu, toast, avatar, badge, separator, tabs, sheet. Set up a custom font (Geist Sans from Vercel) and a custom color palette with primary #7c3aed (violet) and secondary #06b6d4 (cyan). Generate the tailwind.config.ts with these colors as CSS variables."

Prompt 2: "Set up Supabase client with these tables: users (id, email, name, created_at), projects (id, user_id, name, description, status, created_at), subscriptions (id, user_id, stripe_customer_id, stripe_subscription_id, plan, status, current_period_end). Add Row Level Security policies. Add auth helpers for server components."

=== PHASE 2: AUTH & PAYMENTS (1-2 hours) ===
Prompt 3: "Implement full authentication flow using Supabase Auth: login page, signup page, password reset, magic link. Use server actions for form handling. Add middleware to protect routes. Create an auth callback route. Style auth pages professionally."

Prompt 4: "Set up Stripe subscription integration: create checkout session for monthly and annual plans ($12/mo, $99/yr). Create billing portal link. Webhook handler for subscription events. Sync subscription status to Supabase. Create pricing page with plan comparison."

=== PHASE 3: CORE FEATURES (3-5 hours) ===
Prompt 5: "Build the main dashboard page with a sidebar navigation, header with user avatar dropdown, and stats cards (Total Projects, Active, Completed, Revenue). Use Tremor components for stats. Make it responsive."

Prompt 6: "Build the CRUD for [MAIN ENTITY]: list view with search/filter, create form in a sheet/dialog, edit form, delete with confirmation, empty state, loading skeletons. Use server actions for mutations. Revalidate data after changes."

Prompt 7: "Add [CORE FEATURE 1] — [describe in 1-2 sentences]. Use [relevant AI API] for intelligence. Show loading states and error handling. Add optimistic updates where possible."

Prompt 8: "Add [CORE FEATURE 2] — [describe]. Follow the same pattern: server actions, optimistic UI, error boundaries."

=== PHASE 4: POLISH (1-2 hours) ===
Prompt 9: "Add landing page: hero section with animated headline, features grid, pricing section, testimonials (static for now), FAQ accordion, footer. Use Aceternity UI animated components for hero and features."

Prompt 10: "Add empty states for every view: dashboard when no projects, list when no items, search with no results. Use illustrations from unDraw. Add tooltips to icons without labels. Add keyboard shortcuts for power users."

Prompt 11: "Add animations: page transitions (fade), list item stagger on mount, card hover effects, button press feedback, toast slide-in, skeleton loading pulses. Use Framer Motion with reduced-motion support."

=== PHASE 5: SHIP (30 min) ===
Prompt 12: "Add SEO: generateMetadata for each route, opengraph-image, sitemap.ts, robots.ts. Add analytics (Plausible or PostHog snippet). Add error.tsx and not-found.tsx for every route. Add loading.tsx skeletons. Final check: all forms have validation, all mutations have loading states, responsive on mobile (375px)."

SECTION F: RECOMMENDED STACK BY APP TYPE

-- WEB SAAS (most common) --
Frontend: Next.js 14+ (App Router) + TypeScript + Tailwind CSS + shadcn/ui

Error Tracking: Sentry (free tier up to 5K events)
Status Page: https://github.com/nicedoc/statuspage (open-source)

-- MOBILE APP (iOS + Android) --
Framework: Expo (React Native) + TypeScript
UI: NativeWind (Tailwind for React Native — https://github.com/marklawlor/nativewind)
Backend: Supabase (same as web)
Navigation: Expo Router (file-based routing like Next.js)

Push Notifications: Expo Push Notifications + OneSignal (free tier)

Analytics: RevenueCat (subscriptions) + PostHog (product analytics)

-- BROWSER EXTENSION --

Storage: chrome.storage.local + Supabase (optional backend)

Framework: Next.js + TypeScript + Tailwind
Components: Aceternity UI + Magic UI + Tremor (for stats/charts)
Hosting: Vercel
Forms: Tally (free) or custom with Resend for email notifications
Analytics: Plausible
SEO: Next.js built-in metadata + next-sitemap
Blog: MDX (built into Next.js App Router) or Notion-to-blog

SECTION H: AI CODING AGENT TOOLS & WORKFLOW
===================================================================

Cursor IDE: https://cursor.com
  - Best setup: Enable "Agent" mode, use Claude 3.5 Sonnet model
  - Use .cursorrules file to define project conventions
  - Composer (Cmd+I) for multi-file edits, Chat (Cmd+L) for questions

Windsurf (by Codeium): https://codeium.com/windsurf
  - Alternative to Cursor, better for larger codebase navigation
  - Cascade feature for agentic multi-file operations

v0 (by Vercel): https://v0.dev
  - Generate UI components from text descriptions
  - Works with shadcn/ui + Tailwind — copy-paste into your project
  - Best for: Landing pages, dashboard layouts, complex form UIs

bolt.new: https://bolt.new
  - Full-stack app generation from prompts
  - Best for: Prototyping, quick POCs, not production apps

CREW3 (for discovering what ships): https://crew3.xyz
  - See what others are building with AI agents

CRITICAL WORKFLOW TIP:
  For complex features, start with v0 for UI, then use Cursor/Windsurf Agent to wire up logic.
  For full pages, generate in v0 → paste → connect to backend in Cursor.
  For API integrations, use Cursor Agent with @docs references (Stripe, Supabase, OpenAI docs).
